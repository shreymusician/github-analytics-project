01

What you get

  1. What it really is. A plain summary and scope, not the marketing README.
  2. How it works. A step-by-step walkthrough and the key parts, each linked to the code it came from.
  3. Is it alive, tested, runnable? History, contributors, tests, CI, Docker and licence, measured rather than guessed, with scores that show their reasons.
  4. What to read first. The files the rest of the project depends on, ranked from the import graph.
  5. Projects worth studying. Describe a goal and get a ranked list with the score broken into its parts, so you can disagree with it.

02

How it works

  1. Our own algorithms read the project. Stack, import graph, git history, tests and CI are computed by code. Repository code is only read, never run.
  2. Facts become numbered evidence. Secrets are scrubbed, and text from the repository is fenced as untrusted data.
  3. A model only puts words to the facts. It uses your own keys, with automatic failover between providers.
  4. Every sentence must cite evidence. Names, files and numbers have to exist in it, or the sentence is dropped before you see it.
  5. Another model checks the work. A different provider audits the claims, and the facts are cross-checked against GitHub.

The questions asked target facts a report is built to surface, which favours the report. Nobody outside the project has measured it yet, and you can help by rating results with the buttons in the app.

04

Your keys, your cost

Explanations are written by the model providers you choose (Groq, Google Gemini, OpenRouter, all with free tiers). You paste your own keys once; they are stored encrypted and used only for your own jobs, and they are never shown again. If one provider is rate limited, GitHub Intel switches to the next.

No keys? You still get the computed facts: stack, history, tests, CI, scores and the files to read first.

05

Honest limits

  • Scores and ranking weights are first guesses, not calibrated against real opinions yet.
  • Tested mainly on AI and ML projects. Other kinds of projects are unproven.
  • It reads code; it does not run it, so "runnable" means "looks runnable".
  • Start-reading picks can favour central helper files over the best starting point.
  • Daily limits apply while it is young: 20 searches and 10 analyses per person per day.
